# 문서 규칙

`docs/`를 어디에 두고 언제 고치는지 정한다. 문서가 코드와 어긋나거나 끝없이 길어지는 것을 막는 것이 목적이다.

## 구조

문서는 도메인별 폴더의 `README.md` 하나에 쓴다. 너무 길어진 도메인만 파일을 나눈다.

| 폴더 | 다루는 코드 |
|---|---|
| `docs/payment/` | `payment` 도메인 (Toss 연동, 결제 시도, 환불) |
| `docs/order/` | `order` 도메인 |
| `docs/reservation/` | `booking` 도메인 (Redis 예약, 좌석 점유, Lua, 예매, 승차권) |
| `docs/train/` | `train` 도메인 (스케줄, 운임, 열차 캐시) |
| `docs/batch/` | `raillo-batch` Job |
| `docs/worker/` | `*Worker`, `*Scheduler` 같은 비동기, 주기 작업 |
| `docs/infra/` | `k8s/`, `.github/workflows/`, `Dockerfile`, `compose*.yaml` |

코드 규칙은 `docs/`가 아니라 `.agents/rules/`에 둔다. 레이어, 예외, 네이밍은 [code-convention.md](./code-convention.md), 테스트는 [test.md](./test.md)다.

## 언제 고치는가

- 위 표의 코드에서 **계약**(API 응답, 상태 전이, 저장 형식, Redis 키와 값, 처리 순서)이 바뀌면 해당 폴더의 문서를 **같은 PR에서** 고친다.
- 계약이 아닌 내부 구현만 바뀌었으면 고치지 않는다.
- 작업을 시작할 때는 다루는 코드의 문서 폴더를 먼저 읽는다.

## 어떻게 쓰는가

- **덧붙이지 말고 기존 서술을 고쳐 쓴다.** 바뀐 내용을 문서 끝에 추가하지 않는다.
- 코드만 읽어서는 알 수 없는 것만 쓴다. 결정의 이유, 계약, 금지 사항, 함정이 그렇다. 클래스 목록, 시그니처, 코드 복사는 쓰지 않는다.
- 작업 경위, 날짜, 커밋 해시, 진행 상황은 쓰지 않는다. 이력은 git과 이슈가 기록한다.
- 같은 내용은 한 곳에만 쓰고 나머지는 링크한다.
- 길어졌으면 `/docs`로 정리한다.

## 문체

- "-한다" 서술체로 쓴다. 이슈와 PR 본문은 "-습니다"다.
- 새로 쓰는 문장에 가운뎃점(`·`)을 쓰지 않는다. "승인과 취소", "승인, 취소"로 쓴다.
