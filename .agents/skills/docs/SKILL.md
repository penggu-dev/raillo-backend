# Docs

## 현재 상태
- 브랜치: !`git branch --show-current`
- 인자: `$ARGUMENTS`

## 왜 필요한가

AI는 작업할 때마다 문서에 내용을 덧붙이고 지우지는 않는다. 그 세션에서만 의미 있던 경위나 예시가 쌓이면 문서가 길어지고, 긴 문서는 다음 작업에서 핵심 규칙을 묻히게 만든다. 이 스킬은 문서를 **줄이는 방향으로만** 다룬다.

## 판단 기준

문장마다 묻는다. **"이 문장을 지우면 다음 작업자가 실수하는가?"** 아니면 지운다.

**남긴다**
- 코드만 읽어서는 알 수 없는 것: 결정의 이유, 지켜야 할 계약(키 포맷, 상태 전이, 순서), 금지 사항, 함정
- 규칙(반드시, 금지)은 지우지 않는다. 길면 한 문장으로 줄인다.

**지운다**

| 분류 | 예 |
|---|---|
| 세션 맥락 | "이번 작업에서", "~하다가 발견했다", 논의 경위, 날짜, 근거로 단 커밋 해시와 PR 번호. 이력은 git과 이슈가 기록한다 |
| 코드로 알 수 있는 것 | 클래스와 메서드 목록, 시그니처, 상세 파일 트리, 코드를 그대로 옮긴 블록 |
| 중복 | 다른 문서나 같은 문서 안에 이미 있는 내용. 원본 하나만 남기고 링크한다 |
| 과한 예시 | 같은 요점을 보여주는 두 번째 예시부터, 올바름과 틀림을 길게 늘어놓은 표 |
| 현황 목록 | 기존 위반 목록, 진행 상황, TODO. 시간이 지나면 틀린다. 이슈로 옮긴다 |
| 긴 이유 | 이유는 한 문장이면 된다 |
| 낡은 것 | 없는 클래스, 파일, 문서를 가리키는 서술 |

## 규칙

- **새 내용을 추가하지 않는다.** 예외는 코드와 다른 서술을 고치는 것뿐이다. 코드가 원본이다.
- 결과는 원본보다 짧다. 길어지면 정리가 아니다.
- 지울지 애매하면 지우지 않고 제안 목록에 "판단 필요"로 올린다.
- 사용자가 승인하기 전에는 고치지 않는다.

## 절차

1. **대상**: 인자가 경로면 그 문서(디렉터리면 그 아래 전부). 없으면 `git diff origin/develop...HEAD --name-only`에서 대상 경로의 `.md`, `.html`.
2. **읽기**: 문서별 줄 수를 기록한다. 같은 주제의 다른 문서도 함께 읽어 중복을 찾는다. 사실 여부가 걸리면 코드를 연다.
3. **제안** 후 멈춘다.

   ```
   📝 문서 정리 제안 — {대상}

   | 문서 | 줄 수 | 위치 | 분류 | 처리 |
   |---|---|---|---|---|
   | rules/test.md | 249 → 140 | Fixture 목록 | 코드로 알 수 있음 | 삭제 |
   | 〃 | | 기존 위반 2건 | 현황 목록 | 삭제, 이슈로 이동 |
   | 〃 | | 실행 | 중복 (AGENTS.md) | 링크로 교체 |

   판단 필요: {있으면}
   진행할까요?
   ```

4. **적용**: 승인된 것만 고친다. 문체는 [.agents/rules/docs.md](../../rules/docs.md)를 따른다. 중복을 지웠으면 남은 원본으로 링크가 이어지는지, 다른 문서가 지운 절을 가리키지 않는지 확인한다.
5. **보고**: 문서별 `전 → 후` 줄 수와 이슈로 옮길 항목을 알린다. 커밋은 `/commit`(`docs:`)으로 한다.
