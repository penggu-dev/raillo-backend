# Docs

## 현재 상태
- 브랜치: !`git branch --show-current`
- 인자: `$ARGUMENTS`

## 왜 필요한가

AI는 작업할 때마다 문서에 덧붙이기만 하고 지우지 않는다. 그 세션에서만 의미 있던 경위, 예시, 현황이 쌓이면 문서가 길어지고 핵심 규칙이 묻힌다. 이 스킬은 문서를 **줄이고 바로잡는 방향으로만** 다룬다.

문서 구조와 문체의 기준은 [.agents/rules/docs.md](../../rules/docs.md)다. **먼저 읽는다.**

## 판단 기준

문장마다 묻는다. **"이 문장을 지우면 다음 작업자가 실수하는가?"** 아니면 지운다.

| 처리 | 대상 |
|---|---|
| 지운다 | 세션 맥락("이번 작업에서", 경위, 날짜, 근거로 단 커밋 해시와 PR 번호) |
| 지운다 | 코드를 옮긴 것(구현 클래스 목록, 코드 블록, 상세 파일 트리). 도메인 모델의 속성, 행위는 남긴다 |
| 지운다 | 같은 요점의 두 번째 예시, 길게 늘어놓은 올바름/틀림 표 |
| 이슈로 옮긴다 | 현황 목록(기존 위반, 진행 상황, TODO, 상태 표시가 붙은 표) |
| 링크로 바꾼다 | 다른 문서나 같은 문서에 이미 있는 내용. 원본 하나만 남긴다 |
| 옮긴다 | 구조에서 벗어난 절. "알려진 문제" 같은 별도 절은 해당 클래스의 규칙으로, 함정 목록은 해당 규칙의 굵은 글씨로 |
| 고친다 | 코드와 다른 서술, 없는 클래스나 문서를 가리키는 서술, 코드와 다른 용어 |
| 묻는다 | 코드, 주석, 테스트로 확인되지 않는 설계 결정의 이유 |

규칙(반드시, 금지)은 지우지 않는다. 길면 한 문장으로 줄인다.

## 규칙

- **새 내용을 추가하지 않는다.** 예외는 코드와 다른 서술을 고치는 것과, 흩어진 내용을 구조에 맞게 옮기는 것뿐이다.
- **코드가 원본이다.** 사실 여부가 걸리면 코드를 연다. 코드가 틀려 보여도 코드를 고치지 않고 보고한다.
- 결과는 원본보다 짧거나 같다.
- 지울지 애매하면 지우지 않고 "판단 필요"로 올린다.
- 사용자가 승인하기 전에는 고치지 않는다.

## 절차

1. **대상**
   - 인자가 경로면 그 문서. 디렉터리면 그 아래 전부.
   - 인자가 없으면 `git diff origin/develop...HEAD --name-only`에 걸린 `docs/`, `.agents/`, `AGENTS.md`, `README.md`.
2. **읽기**
   - 문서별 줄 수를 기록한다.
   - 같은 주제의 다른 문서도 읽어 중복을 찾는다. `AGENTS.md`의 문서 지도와 `rules/docs.md`의 폴더 표도 본다.
   - 서술이 가리키는 클래스, 키, 설정을 코드에서 확인한다.
3. **링크 확인**: 저장소 전체(소스 주석, 모듈 README, `.github` 포함)에서 문서 경로를 찾아, 가리키는 파일과 절이 모두 있는지 본다.

   ```bash
   git grep -nE "docs/[A-Za-z/-]+\.(md|html)"
   ```

4. **제안** 후 멈춘다.

   ```
   📝 문서 정리 제안 — {대상}

   | 문서 | 줄 수 | 위치 | 분류 | 처리 |
   |---|---|---|---|---|
   | payment/README.md | 180 → 157 | 알려진 공백 절 | 구조 이탈 | 각 클래스 규칙으로 옮김 |
   | 〃 | | 결제 시도 규칙 | 코드와 다름 | `attemptId`는 서버가 계산 → 수정 |
   | worker/README.md | | 런북 링크 | 없는 문서 | 링크 삭제 |

   이슈로 옮길 것: {있으면}
   판단 필요: {있으면}
   진행할까요?
   ```

5. **적용**: 승인된 것만 고친다. 지우거나 옮긴 절을 다른 문서, `AGENTS.md`, 소스 주석이 가리키지 않는지 다시 확인한다.
6. **보고**: 문서별 `전 → 후` 줄 수, 고친 링크, 이슈로 옮길 항목을 알린다. 커밋은 `/commit`(`docs:`)으로 한다.
